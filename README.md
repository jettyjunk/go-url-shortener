# go-url-shortener

Сервис сокращения ссылок на Go: принимает длинный URL, выдаёт короткий код и перенаправляет по нему на оригинал. Pet-проект, в котором я отрабатываю слоистую архитектуру, работу с PostgreSQL, обработку ошибок и тестирование бизнес-логики.

## Возможности

- Создание короткой ссылки: `POST /shorten`
- Редирект по короткому коду: `GET /{code}`
- Валидация URL (только `http` и `https`, обязательный хост)
- Случайные непредсказуемые коды с повтором при коллизии
- Миграции схемы БД, окружение поднимается одной командой

## Стек

- Go 1.22+ (стандартный `net/http` и роутер с паттернами `GET /{code}`)
- PostgreSQL 18, драйвер [pgx v5](https://github.com/jackc/pgx)
- [golang-migrate](https://github.com/golang-migrate/migrate) для миграций
- Docker Compose, Makefile

## Быстрый старт

Нужны: Go 1.22+, Docker, CLI `migrate`:

```bash
go install -tags 'postgres' github.com/golang-migrate/migrate/v4/cmd/migrate@latest
```

Запуск:

```bash
cp .env.example .env     # заполнить значения
make up                  # поднять PostgreSQL в Docker
make migrate-up          # накатить миграции
make run                 # запустить сервис
```

Сервис слушает адрес из `HTTP_ADDR` (по умолчанию `:5050`).

### Переменные окружения

| Переменная | Описание | Пример |
|---|---|---|
| `HTTP_ADDR` | адрес HTTP-сервера | `:5050` |
| `BASE_URL` | начало короткой ссылки в ответах | `http://localhost:5050` |
| `HTTP_SHUTDOWN_TIMEOUT` | таймаут остановки сервера (пока зарезервирован) | `30s` |
| `POSTGRES_USER` | пользователь БД | `admin` |
| `POSTGRES_PASSWORD` | пароль БД | |
| `POSTGRES_DB` | имя БД | `shortener` |

### Команды Makefile

| Команда | Что делает |
|---|---|
| `make up` / `make down` | поднять / остановить PostgreSQL |
| `make migrate-up` / `make migrate-down` | накатить / откатить миграции |
| `make psql` | открыть `psql` внутри контейнера |
| `make run` | запустить приложение |

## API

### `POST /shorten`

Создаёт короткую ссылку.

```bash
curl -i -X POST localhost:5050/shorten -d '{"url":"https://example.com"}'
```

Ответ `201 Created`:

```json
{"short_url": "http://localhost:5050/aB3xK9q"}
```

| Статус | Когда |
|---|---|
| `201` | ссылка создана |
| `400` | некорректный JSON или невалидный URL |
| `500` | внутренняя ошибка |

### `GET /{code}`

Перенаправляет на исходный URL.

```bash
curl -i localhost:5050/aB3xK9q
```

| Статус | Когда |
|---|---|
| `302` | редирект, адрес в заголовке `Location` |
| `404` | такого кода нет |
| `500` | внутренняя ошибка |

## Архитектура

Три слоя, зависимости направлены в одну сторону:

```
handler  →  service  →  repository  →  PostgreSQL
```

```
cmd/app/            точка входа, сборка зависимостей
config/             чтение и проверка переменных окружения
internal/
├── handler/        HTTP: разбор запроса, перевод ошибок в статусы
├── service/        бизнес-логика: валидация URL, генерация кода, повтор при коллизии
├── repository/     SQL-запросы (pgx)
└── codegen/        генерация случайных кодов
migrations/         SQL-миграции
```

- **handler** ничего не знает про SQL, **repository** ничего не знает про HTTP.
- Интерфейсы объявлены там, где используются (потребителем), поэтому сервис тестируется без базы, с заглушкой вместо репозитория.
- Репозиторий возвращает собственные ошибки (`ErrCodeExists`, `ErrNotFound`), чтобы верхние слои не зависели от драйвера БД.

## Принятые решения

**Случайный код, а не id.** Код это 7 символов из `0-9a-zA-Z`, сгенерированных через `crypto/rand` (около 3,5 трлн вариантов). Последовательные id позволили бы перебрать чужие ссылки и узнать, сколько их создано. Минус: приходится обрабатывать коллизии. Остаточный перекос от `% 62` при выборе символа допустим для такой задачи.

**Коллизии.** На колонке `code` стоит `UNIQUE`. При нарушении ограничения (код ошибки Postgres `23505`) репозиторий возвращает `ErrCodeExists`, а сервис генерирует новый код и повторяет попытку, до 5 раз.

**Редирект 302, а не 301.** 301 браузеры кешируют навсегда и в следующий раз ходят напрямую, минуя сервис. С 302 каждый переход проходит через сервис, а значит, позже можно считать клики и менять адрес назначения.

**Валидация URL.** Недостаточно `url.ParseRequestURI`: он пропускает `javascript:...` и адреса без хоста. Дополнительно проверяются схема (`http`/`https`) и непустой хост.

**Контекст и таймауты.** Контекст запроса передаётся от хендлера до БД, поэтому запрос прерывается, если клиент ушёл. Поверх него в репозитории стоит таймаут 5 секунд на запрос.

**Ошибки обрабатываются один раз.** Слои оборачивают ошибки (`%w`) и возвращают наверх, логирует их хендлер (для запросов) или `main` (для запуска). Клиенту при `500` отдаётся общий текст без деталей.

## Тесты

```bash
go test ./internal/...
```
